# 정책

풀문 공유 경제 생태계의 설계 결정과 그 근거. 외부 개발자가 지켜야 할 것과
운영자가 약속할 것을 정리한다.

## 왜 읽기 전용인가 (2026-07-12 결정)

economy-api는 nginx를 통해 `https://api.fullmoon.ink/economy/`로 인터넷에 공개돼
있다. 과거에는 `/v1/grant`, `/v1/revoke`, `/v1/transfer`, 설정 쓰기도 노출됐다 —
그동안은 베어러 키 하나가 곧 조폐권이었다. 키가 새면 원장이 샌다.

경제의 주인이 한 명인 이상, 인터넷에서 잔액을 움직일 수 있는 표면은 위험만
사고 편의는 사지 않는다. 그래서 쓰기 엔드포인트를 전부 제거했다. 지금은 키가
새도 새는 건 읽기뿐이다.

코드에도 쓰기 경로가 남아 있지 않다: 서버 프로세스는 `wallet.js`를 import하지
않고, GET이 아닌 요청은 인증·본문 파싱 이전에 405로 끊긴다.

**지급 경로가 필요한 기능은** 운영자와 합의해서 코인브릿지 봇 안에 수급처를
만든다. API로 우회하지 않는다.

## 3가지 철칙 (외부 통합이 지킬 것)

1. **잔액을 캐시하지 말 것.** 잔액을 바꾸는 건 여러분 프로세스가 아니다. 캐시는
   반드시 틀려진다 — 표시 직전에 조회한다.
2. **자체 화폐/잔액 테이블을 만들지 말 것.** 그 순간 단일 경제가 깨진다. 여러분
   DB에는 돈이 아닌 것만 남긴다(미니게임 상태, 쿨다운, 설정).
3. **숫자를 하드코딩하지 말 것.** 배수·캡은 `/v1/config`에서 읽는다(30초 캐시).
   운영자가 값을 바꾸면 여러분 UI도 같이 움직인다.

이 규칙은 [통합 카탈로그](https://github.com/Fullmoon-OSS/fullmoon-sdk/blob/main/INTEGRATIONS.md)
등록 유지 조건이기도 하다.

## 키 발급·교체 절차

1. **발급** — 봇 이름을 정해 운영진에게 알린다. 운영자는 32자 이상 랜덤 키를
   생성해 레지스트리에 등록하고 키를 전달한다.
   ```bash
   node -e "console.log(require('crypto').randomBytes(24).toString('base64url'))"
   ```
2. **교체** — 키 유출이 의심되면 즉시 운영진에 알린다. 운영자가 레지스트리에서
   해당 키를 갈아끼운다. 서버 재시작 없이는 안 되므로 새 키 발급과 함께 짧은
   다운타임이 있을 수 있다.
3. **폐기** — 서비스를 접으면 키를 레지스트리에서 제거한다.

## 레이트리밋

| 계층 | 한도 |
|---|---|
| 앱 (클라이언트별) | 기본 60req/10s |
| nginx (IP별) | 10 req/s, burst 40 |

정상 봇 트래픽으로는 닿을 일이 없다. 닿았다면 폴링 루프를 돌리고 있다는 뜻이다 —
백오프하고, 필요하면 상향을 요청하라. 폴링 권장 주기는 5초 이상이다.

## vocabulary 동기화

원장의 거래 사유 코드와 그 한글 표시명(`txLabel`), mint/burn 분류(`TX_FILTERS`)는
운영 봇이 정의한다. API 레포의 `src/vocabulary/`는 그 **동기화 사본**이다.
정의를 바꿀 때는 봇 쪽에서 고치고 API 레포로 byte-for-byte 복사한다 — 사본이
따로 놀면 대시보드 숫자가 `/경제현황`과 어긋난다.
